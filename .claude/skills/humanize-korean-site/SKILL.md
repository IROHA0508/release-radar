# 릴리스 레이더 문체 규칙 (im-not-ai 적용판)

규칙 원본은 [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 `humanize-korean` 스킬이다(MIT, `LICENSE-im-not-ai`).
`references/quick-rules.md`는 원본 v2.3.2(커밋 b37e020)의 룰북을 그대로 복사한 것이다. 이 파일만 고치지 말고 원본이 바뀌면 통째로 다시 복사한다.

## 이 사이트에 맞춘 적용 범위

- **장르는 리포트.** 소식·기술 페이지는 목록(changes, tips, how …)이 의도된 구조다. C-2(불릿을 산문으로)와 E-1(장문 섞기)은 목록 항목에는 적용하지 않고 tldr·why·definition 같은 문단에만 적용한다.
- **존댓말(합쇼체) 유지.** "~합니다/~입니다"를 평어체로 바꾸지 않는다(register 보존).
- **절대 바꾸지 않는 것:** 수치, 날짜, 가격, 모델명, API ID, 제품명, URL, 코드 블록, 프롬프트 예시 원문, 원문 직접 인용. 서법도 그대로 둔다("~할 수 있다"를 단정으로 바꾸지 않는다).
- **원본이 기각한 신호는 보지 않는다:** A-2 "~를 통해", I-1 "~것이다", H-1 문두 접속사, J-2 따옴표, D-4 hype 어휘.

## 이 사이트에서 자주 걸리는 패턴 (2026-10-22 점검)

| ID | 무엇 | 처방 |
|---|---|---|
| C-11 | 연결어미(-고/-며/-지만/-면서/-아서/-어서) 뒤 쉼표 | 쉼표를 지운다. 새 쉼표를 만들지 않는다 |
| C-10 | 제목마다 "X: Y" 콜론 부제 | 하나의 명사구나 문장으로 합친다 |
| C-8 | "A가 아니라 B" 대구가 한 문서에 2번 이상 | 하나만 두고 나머지는 평서문으로 |
| D-8 | "핵심은 ~", "중요한 것은 ~" 분열문 | 주어-서술로 바로 쓴다 |
| D-9 | "~로 이어집니다" 결산 | 인과를 구체적으로 쓰거나 단문으로 |
| A-10 | 한 문서에 "~할 수 있습니다" 4번 이상 | 일부만 "~할 수도 있습니다", "~가 가능합니다" 등으로 분산(단정 금지) |
| F-5 | "~적 N" 추상 체인 | 명사+명사나 풀어쓰기 |

## 쓰는 법

1. 글을 쓰거나 고친 뒤 `python3 scripts/style_check.py --spans`로 신호를 확인한다.
2. 걸린 문장만 고친다. 걸리지 않은 문장은 한 글자도 바꾸지 않는다(원본 철칙 '근거 기반').
3. 바뀐 글자 비율은 30% 안으로 둔다. 원문 대비 수치·ID·URL이 하나라도 달라졌으면 그 수정은 되돌린다.
4. `python3 scripts/validate_data.py`로 검증한다.

자동 업데이트(`backend/`)는 기사를 쓸 때 `references/quick-rules.md`를 프롬프트에 함께 넣고 쓴 뒤 `scripts/style_check.py`와 같은 검사로 S1 신호가 남으면 한 번 더 다듬는다(`backend/humanize.py`).

전체 파이프라인(진단 → 윤문 → 검증)이 필요하면 원본 플러그인을 설치해 쓴다.

```
/plugin marketplace add epoko77-ai/im-not-ai
/plugin install humanize-korean@im-not-ai
```
